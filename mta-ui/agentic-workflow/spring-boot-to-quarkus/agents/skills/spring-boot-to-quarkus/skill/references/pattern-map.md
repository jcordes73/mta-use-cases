# Pattern Map — Spring Boot 3.x to Quarkus 3.x

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Replace Spring Boot parent POM with Quarkus BOM in dependencyManagement | structural | `<parent><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter-parent</artifactId><version>3.x.x</version></parent>` | `<dependencyManagement><dependencies><dependency><groupId>io.quarkus.platform</groupId><artifactId>quarkus-bom</artifactId><version>${quarkus.platform.version}</version><type>pom</type><scope>import</scope></dependency></dependencies></dependencyManagement>` | Add `quarkus.platform.version` property to `<properties>` | Replace the Spring Boot parent with the Quarkus BOM |
| Replace Spring Boot Maven plugin with Quarkus Maven plugin | structural | `<plugin><groupId>org.springframework.boot</groupId><artifactId>spring-boot-maven-plugin</artifactId></plugin>` | `<plugin><groupId>io.quarkus.platform</groupId><artifactId>quarkus-maven-plugin</artifactId><version>${quarkus.platform.version}</version><extensions>true</extensions><executions><execution><goals><goal>build</goal><goal>generate-code</goal><goal>generate-code-tests</goal></goals></execution></executions></plugin>` | | Replace the Spring Boot plugin with the Quarkus plugin |
| Set Maven compiler version to Java 17+ for Quarkus 3.x | structural | `<maven.compiler.source>11</maven.compiler.source>` | `<maven.compiler.source>17</maven.compiler.source>` | Quarkus 3.x requires Java 17 minimum | Change the Java version |
| Remove @SpringBootApplication entry point; Quarkus provides its own | structural | `@SpringBootApplication public class MyApp { public static void main(String[] args) { SpringApplication.run(MyApp.class, args); } }` | `@QuarkusMain public class MyApp implements QuarkusApplication { @Override public int run(String... args) { Quarkus.waitForExit(); return 0; } }` | Or simply delete the main class — Quarkus auto-provides entry point | Application Entry Point |
| Spring DI @Configuration with @Bean methods → CDI @ApplicationScoped with @Produces | structural | `@Configuration public class AppConfig { @Bean public MyService myService() { return new MyServiceImpl(); } }` | `@ApplicationScoped public class AppConfig { @Produces public MyService myService() { return new MyServiceImpl(); } }` | Or use `quarkus-spring-di` extension for compatibility | Dependency Injection |
| Constructor injection pattern stays similar but annotations change | structural | `@Service public class MyService { @Autowired public MyService(MyRepo repo) { this.repo = repo; } }` | `@ApplicationScoped public class MyService { @Inject public MyService(MyRepo repo) { this.repo = repo; } }` | Constructor injection is preferred in both frameworks | Dependency Injection |
| Spring REST controller → JAX-RS resource class | structural | `@RestController @RequestMapping("/api") public class ItemController { @GetMapping("/{id}") public ResponseEntity<Item> get(@PathVariable Long id) { return ResponseEntity.ok(service.find(id)); } }` | `@Path("/api") @Produces(MediaType.APPLICATION_JSON) public class ItemResource { @GET @Path("/{id}") public Response get(@PathParam("id") Long id) { return Response.ok(service.find(id)).build(); } }` | Or use `quarkus-spring-web` extension to keep Spring MVC annotations | Web / REST |
| Spring MVC exception handling → JAX-RS ExceptionMapper | structural | `@ControllerAdvice public class ErrorHandler { @ExceptionHandler(NotFoundException.class) public ResponseEntity<?> handle(NotFoundException e) { return ResponseEntity.notFound().build(); } }` | `@Provider public class NotFoundExceptionMapper implements ExceptionMapper<NotFoundException> { @Override public Response toResponse(NotFoundException e) { return Response.status(404).build(); } }` | Each exception type needs its own ExceptionMapper implementation | Web / REST |
| Spring @Value config injection → MicroProfile @ConfigProperty | structural | `@Value("${app.greeting}") private String greeting;` | `@ConfigProperty(name = "app.greeting") String greeting;` | `@Inject` not required on `@ConfigProperty` fields in Quarkus | Configuration |
| Spring @ConfigurationProperties → Quarkus @ConfigMapping interface | structural | `@ConfigurationProperties(prefix = "app") public class AppConfig { private String name; public String getName() { return name; } public void setName(String name) { this.name = name; } }` | `@ConfigMapping(prefix = "app") public interface AppConfig { String name(); }` | Quarkus `@ConfigMapping` uses interfaces, not classes. Cannot use setters | Configuration |
| Thymeleaf th:text/th:if/th:each → Qute expression/if/for syntax | structural | `<div th:text="${user.name}">Default</div><div th:if="${user.active}">Active</div><li th:each="item : ${items}" th:text="${item.title}">Item</li>` | `<div>{user.name}</div>{#if user.active}Active{/if}{#for item in items}<li>{item.title}</li>{/for}` | Template files move from `src/main/resources/templates/` (same location) | Thymeleaf to Qute Migration |
| Thymeleaf fragment inclusion → Qute include | structural | `<div th:include="fragments/header :: header"></div>` | `{#include fragments/header /}` | | Thymeleaf to Qute Migration |
| Thymeleaf i18n → Qute message bundles | structural | `<span th:text="#{welcome.message}">Welcome</span>` | `<span>{msg:welcome_message}</span>` | Create `messages.properties` in `src/main/resources/messages/` | Thymeleaf to Qute Migration |
| Spring MVC Controller with Model → Quarkus @Path with Qute TemplateInstance | structural | `@Controller public class PageController { @GetMapping("/page") public String page(Model model) { model.addAttribute("data", service.getData()); return "page"; } }` | `@Path("/page") public class PageController { @Inject Template page; @GET @Produces(MediaType.TEXT_HTML) public TemplateInstance page() { return page.data("data", service.getData()); } }` | Inject `Template` by field name matching the template file name | Thymeleaf to Qute Migration |
| Spring @Cacheable/@CacheEvict → Quarkus @CacheResult/@CacheInvalidate | structural | `@Cacheable("items") public List<Item> getItems() { ... } @CacheEvict("items") public void clearItems() { ... }` | `@CacheResult(cacheName = "items") public List<Item> getItems() { ... } @CacheInvalidate(cacheName = "items") public void clearItems() { ... }` | Or use `quarkus-spring-cache` for compatibility | Caching |
| Spring @Scheduled → Quarkus @Scheduled with different attributes | structural | `@Scheduled(fixedRate = 5000) public void process() { ... }` | `@io.quarkus.scheduler.Scheduled(every = "5s") void process() { ... }` | Quarkus uses duration strings (`5s`, `1m`, `1h`) instead of milliseconds | Scheduling |
| Spring @EventListener → CDI @Observes parameter annotation | structural | `@EventListener public void onUserCreated(UserCreatedEvent event) { ... }` | `public void onUserCreated(@Observes UserCreatedEvent event) { ... }` | CDI uses parameter annotation; Spring uses method annotation | Events |
| Spring ApplicationEventPublisher → CDI Event injection | structural | `@Autowired ApplicationEventPublisher publisher; publisher.publishEvent(new UserCreatedEvent(user));` | `@Inject Event<UserCreatedEvent> event; event.fire(new UserCreatedEvent(user));` | | Events |
| Spring Boot DevTools live reload → Quarkus dev mode (built-in) | behavioral | `mvn spring-boot:run` (with devtools on classpath) | `mvn quarkus:dev` | Quarkus dev mode includes live reload, Dev UI at `/q/dev`, Dev Services, continuous testing | Dev Mode |
| Spring Boot Actuator health endpoint path changes | behavioral | `/actuator/health` | `/q/health` | Liveness at `/q/health/live`, readiness at `/q/health/ready` | Health and Metrics |
| Spring Boot Actuator metrics endpoint path changes | behavioral | `/actuator/metrics` | `/q/metrics` | Uses Micrometer; same metrics API, different endpoint path | Health and Metrics |
| Custom HealthIndicator → Quarkus @Liveness/@Readiness health check | structural | `@Component public class MyHealth implements HealthIndicator { @Override public Health health() { return Health.up().build(); } }` | `@Liveness @ApplicationScoped public class MyHealth implements HealthCheck { @Override public HealthCheckResponse call() { return HealthCheckResponse.up("my-check"); } }` | MicroProfile Health API; use `@Liveness` or `@Readiness` annotation | Health and Metrics |
| Spring @SpringBootTest → Quarkus @QuarkusTest for integration tests | structural | `@SpringBootTest @AutoConfigureMockMvc class MyTest { @Autowired MockMvc mockMvc; @MockBean MyService service; }` | `@QuarkusTest class MyTest { @InjectMock MyService service; @Test void test() { given().when().get("/api").then().statusCode(200); } }` | MockMvc replaced by REST Assured; `@MockBean` replaced by `@InjectMock` | Testing |
| MockMvc HTTP testing → REST Assured HTTP testing | structural | `mockMvc.perform(get("/api/items")).andExpect(status().isOk()).andExpect(jsonPath("$[0].name").value("test"))` | `given().when().get("/api/items").then().statusCode(200).body("[0].name", equalTo("test"))` | REST Assured is the standard HTTP testing library in Quarkus | Testing |
| Spring test profile activation → Quarkus TestProfile class | structural | `@ActiveProfiles("test")` | `@TestProfile(TestConfig.class)` where `TestConfig implements QuarkusTestProfile` | Override config in `QuarkusTestProfile.getConfigOverrides()` | Testing |
| Spring @DataJpaTest slice test → full @QuarkusTest with @Transactional | structural | `@DataJpaTest class RepoTest { @Autowired MyRepo repo; }` | `@QuarkusTest class RepoTest { @Inject MyRepo repo; @Test @Transactional void test() { ... } }` | No slice testing in Quarkus; use Dev Services for test databases | Testing |
| Maven compile command changes from spring-boot to quarkus | behavioral | `mvn spring-boot:run` | `mvn quarkus:dev` | Production build: `mvn package -Dquarkus.package.type=uber-jar` or `mvn package -Dnative` | Dev Mode |
| Spring Boot fat JAR packaging → Quarkus packaging | behavioral | `mvn package` (produces `app.jar` with spring-boot-maven-plugin) | `mvn package` (produces `app-runner.jar` with quarkus-maven-plugin) | Quarkus supports uber-jar, fast-jar (default), and native image packaging | Dev Mode |
| Two migration paths available: pure Quarkus (high effort) or Quarkus Spring compat (moderate effort) | addition | | | Use Spring compatibility extensions (`quarkus-spring-di`, `quarkus-spring-web`, `quarkus-spring-data-jpa`) as a stepping stone, then gradually refactor to native Quarkus APIs | Migration Paths |
| Add Quarkus version property to pom.xml | addition | | `<quarkus.platform.version>3.x.x</quarkus.platform.version>` | Set to the latest Quarkus 3.x release | Set the Quarkus version |
| OSIV (Open Session in View) not available in Quarkus | removal | `spring.jpa.open-in-view=true` | N/A | Lazy loading outside `@Transactional` will fail. Fetch data eagerly or use `@Transactional` | JPA / Hibernate |
| Spring Boot auto-configuration not available | removal | Spring Boot auto-detects and configures beans based on classpath | N/A | Quarkus uses build-time extension configuration; beans must be explicitly defined or come from extensions | Dependency Injection |
| Spring Boot conditional beans (@ConditionalOnProperty, etc.) not supported | removal | `@ConditionalOnProperty(name = "feature.enabled")` | N/A | Use Quarkus build-time conditions or CDI alternatives (`@IfBuildProfile`, `@UnlessBuildProfile`) | Dependency Injection |
| License compatibility check required before migration | addition | | | Quarkus uses Apache License 2.0. Verify your project license is compatible (Apache 2.0, MIT, BSD are fine; GPL/proprietary need legal review) | Constraints |
| Multi-module Maven projects require manual migration | addition | | | Automated migration tools don't support multi-module projects. Each module must be migrated individually | Constraints |
