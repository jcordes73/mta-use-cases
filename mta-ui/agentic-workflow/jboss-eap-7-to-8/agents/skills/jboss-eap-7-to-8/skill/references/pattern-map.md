# Pattern Map — JBoss EAP 7 to 8

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| JDK 8 no longer supported; JDK 11 minimum, JDK 17 recommended | addition | | Compile and deploy with JDK 11+ (JDK 17 recommended) | JDK 11 deprecated but still supported; Java SE 21 planned for future EAP 8 release | JDK Requirements |
| Jakarta EE 8 → Jakarta EE 10: all `javax.*` EE packages → `jakarta.*` | structural | `import javax.servlet.http.HttpServletRequest;` | `import jakarta.servlet.http.HttpServletRequest;` | Does NOT affect Java SE `javax.*` packages (javax.xml.datatype, javax.crypto, javax.sql, javax.naming, javax.security.auth, javax.annotation.processing, javax.transaction.xa) | Jakarta EE Namespace |
| CDI 4.0 bean discovery default changed from `all` to `annotated` for empty beans.xml | behavioral | Empty `beans.xml` discovers all beans | Empty `beans.xml` only discovers annotated beans | Add `bean-discovery-mode="all"` to beans.xml or add CDI annotations (`@ApplicationScoped`, `@RequestScoped`, etc.) to all beans | CDI 4.0 Changes |
| PicketBox legacy security removed; migrate to Elytron | removal | `<security-domain name="other">` with PicketBox login modules | Configure Elytron `security-domain` with `jaas-realm`, `jdbc-realm`, `ldap-realm`, or `key-store-realm` | Server Migration Tool auto-migrates basic configs; custom login modules need `jaas-realm` (not PicketBox-dependent ones) | Security Removal |
| PicketLink removed; use Keycloak for SSO | removal | PicketLink identity provider and service provider | Red Hat build of Keycloak for IdP; `keycloak-saml` subsystem replaces `picketlink-federation` | SAML support via RH-SSO SAML Galleon Feature Pack | Security Removal |
| OIDC adapter moved from RH-SSO adapter to `elytron-oidc-client` subsystem | structural | RH-SSO OIDC adapter (`keycloak` subsystem) | `elytron-oidc-client` subsystem for native OIDC support | No external adapter needed; built into EAP 8 | OIDC Migration |
| PicketBox vault replaced by Elytron credential store | structural | `<vault><vault-option name="..." value="..."/></vault>` | `<credential-store>` in Elytron subsystem | Migrate stored credentials to Elytron credential stores | Security Removal |
| Custom login modules: use `jaas-realm` in Elytron | structural | Custom `LoginModule` in PicketBox security domain | Configure `jaas-realm` in Elytron subsystem | `jaas-realm` does NOT support modules extending PicketBox APIs; prefer `jdbc-realm`, `ldap-realm` | Security Removal |
| Jolokia monitoring removed | removal | Jolokia agent for JMX-over-HTTP monitoring | Use built-in `/metrics` endpoint at `<server>:<mgmt-port>/metrics` | Red Hat no longer supports Jolokia | Monitoring Changes |
| Prometheus subsystem removed | removal | Prometheus metrics subsystem in EAP 7 | Use built-in `/metrics` endpoint | Red Hat no longer supports Prometheus subsystem | Monitoring Changes |
| Apache Log4j v1 APIs removed from EAP | removal | `log4j.properties` or `log4j.xml` for Log4j 1 | Package Log4j 2 within application or use JBoss Logging | Apps not packaging `log4j.jar` within the deployment must update | Log4j Removal |
| Hibernate ORM upgraded from 5.x to 6.x | structural | Hibernate 5 APIs and HQL syntax | Hibernate 6 APIs with updated HQL and Criteria API | Major breaking changes; see Hibernate 6 migration guide | Hibernate Upgrade |
| Hibernate Search upgraded from 5.x to 6.x (backwards-incompatible) | structural | `org.hibernate.search.jpa.FullTextEntityManager` | `org.hibernate.search.mapper.orm.Search.session(entityManager)` | Hibernate Search 6 APIs are completely different from 5.x | Hibernate Search |
| XML binding namespace changed for JAXB files | structural | `xmlns:jaxb="http://java.sun.com/xml/ns/jaxb"` | `xmlns:jaxb="https://jakarta.ee/xml/ns/jaxb"` | Update all JAXB binding customization files | XML Namespace Changes |
| ServiceLoader files must use `jakarta.*` names | structural | `META-INF/services/javax.ws.rs.ext.Providers` | `META-INF/services/jakarta.ws.rs.ext.Providers` | Rename all `META-INF/services/javax.*` files | Jakarta EE Namespace |
| `web.xml` namespace must be updated | structural | `xmlns="http://xmlns.jcp.org/xml/ns/javaee"` | `xmlns="https://jakarta.ee/xml/ns/jakartaee"` | Update `web.xml`, `ejb-jar.xml`, `persistence.xml`, and other EE deployment descriptors | XML Namespace Changes |
| `persistence.xml` namespace and version updated | structural | `xmlns="http://xmlns.jcp.org/xml/ns/persistence" version="2.2"` | `xmlns="https://jakarta.ee/xml/ns/persistence" version="3.1"` | Update namespace and version attribute | XML Namespace Changes |
| Maven BOM: `jboss-eap-jakartaee8` → `jboss-eap-ee` | structural | `<artifactId>jboss-eap-jakartaee8</artifactId>` | `<artifactId>jboss-eap-ee</artifactId>` | Also update version to `8.0.0.GA-redhat-00009` | Maven Artifact Changes |
| Maven BOM: `jboss-eap-jakartaee8-with-tools` → `jboss-eap-ee-with-tools` | structural | `<artifactId>jboss-eap-jakartaee8-with-tools</artifactId>` | `<artifactId>jboss-eap-ee-with-tools</artifactId>` | | Maven Artifact Changes |
| EAP 6 BOMs (`jboss-javaee-6.0-with-*`) must be replaced | structural | `<artifactId>jboss-javaee-6.0-with-tools</artifactId>` | `<artifactId>jboss-eap-ee-with-tools</artifactId>` | groupId also changes: `org.jboss.bom.eap` → `org.jboss.bom` | Maven Artifact Changes |
| `SOAPElementFactory` removed; use `SOAPFactory` | removal | `javax.xml.soap.SOAPElementFactory.newInstance()` | `jakarta.xml.soap.SOAPFactory.newInstance()` | Deprecated class fully removed | Jakarta EE API Removals |
| `javax.xml.bind.Validator` interface removed | removal | `JAXBContext.createValidator()` | Remove usage; use schema validation directly | JAXB 1.0 compatibility fully removed | Jakarta EE API Removals |
| New `eap-maven-plugin` for Galleon-based server provisioning | addition | Legacy Maven plugin for EAP deployment | `eap-maven-plugin` with Galleon layers for trimmed servers | Supports CLI script execution and reduced image size for OpenShift | Server Provisioning |
| OpenShift S2I images redesigned; no longer contain EAP binaries | structural | OpenShift images with pre-installed EAP runtime | EAP provisioned at build time via `eap-maven-plugin` | Reduced image size and attack surface | Cloud Deployment |
| Server Migration Tool is standalone download (not bundled) | structural | Migration tool bundled with EAP | Download separately from EAP downloads page | Run: `./jboss-server-migration.sh -s $EAP_PREVIOUS_HOME -t $JBOSS_HOME` | Server Migration |
| `jboss-web-policy` and `jboss-ejb-policy` authorization migration not supported | behavioral | Legacy security domain authorization | Manual migration required to Elytron | Server Migration Tool cannot auto-migrate these | Security Removal |
| `authentication-jaspi` (JASPI) migration not supported by tool | behavioral | JASPI authentication config (`jaspitest`) | Manual migration required to Elytron | | Security Removal |
| WildFly module lazy loading changes classloading behavior | behavioral | All modules eagerly loaded | Modules loaded lazily for smaller footprint | May cause `ClassNotFoundException` for implicit module dependencies | Classloading Changes |
| `@Stateful` EJB behavioral changes under load | behavioral | `@Stateful` beans with `SessionScoped` injection | Test thoroughly under production load conditions | Extended persistence contexts and session injection may behave differently | EJB Changes |
| Eclipse Transformer available for bytecode-level namespace transformation | addition | | Use Eclipse Transformer for third-party JARs without source code | Alternative when source migration is not possible for dependencies | Jakarta EE Namespace |
| Faces: JSP support removed from Jakarta Faces 4.0 | removal | JSP-based Faces views (`*.jsp`) | Migrate all Faces views to Facelets (`*.xhtml`) | JSP as a view technology for Faces is no longer supported | Faces Removals |
| Faces Managed Beans removed; use CDI | removal | `@ManagedBean @RequestScoped public class MyBean` | `@Named @RequestScoped public class MyBean` | All `javax.faces.bean.*` scope annotations replaced by CDI scope equivalents | Faces Removals |
| Servlet 6.0: `SingleThreadModel` interface removed | removal | `public class MyServlet extends HttpServlet implements SingleThreadModel` | Remove `implements SingleThreadModel`; use proper synchronization | Thread-safety mechanism removed; was deprecated since Servlet 2.4 | Servlet 6.0 Removals |
| Servlet 6.0: `HttpSessionContext` interface removed | removal | `session.getSessionContext()` | Remove usage; no replacement | Deprecated interface removed for security reasons | Servlet 6.0 Removals |
| Servlet 6.0: `HttpUtils` class removed | removal | `HttpUtils.parseQueryString(query)` | Parse query strings manually or use framework utilities | Deprecated utility class fully removed | Servlet 6.0 Removals |
| JAXB implementation package: `com.sun.xml.bind` → `org.glassfish.jaxb.runtime` | structural | `import com.sun.xml.bind.v2.ContextFactory;` | `import org.glassfish.jaxb.runtime.v2.ContextFactory;` | Affects apps accessing JAXB impl directly; sub-packages follow same pattern | JAXB Implementation |
| JAXB Marshaller property prefix changed | structural | `marshaller.setProperty("com.sun.xml.bind.namespacePrefixMapper", mapper)` | `marshaller.setProperty("org.glassfish.jaxb.namespacePrefixMapper", mapper)` | All `com.sun.xml.bind.*` property constants → `org.glassfish.jaxb.*` | JAXB Implementation |
| JAXB 1.0 compatibility removed; JAXBContext lookup simplified | removal | `jaxb.properties` file, `javax.xml.bind.context.factory`, `/META-INF/services/javax.xml.bind.JAXBContext` | Use standard Jakarta XML Binding 4.0 discovery algorithm | Legacy lookup via properties files and service files dropped | JAXB Implementation |
| JSON Binding: `@JsonbCreator` no longer requires all constructor params | behavioral | `@JsonbCreator` constructor required all parameters by default | `@JsonbCreator` allows partial params; use `withCreatorParametersRequired(true)` for old behavior | May affect deserialization of classes with `@JsonbCreator` constructors | JSON Binding Changes |
| OIDC: Keycloak adapter → native `elytron-oidc-client` | structural | `<auth-method>KEYCLOAK</auth-method>` in `web.xml` and `WEB-INF/keycloak.json` | `<auth-method>OIDC</auth-method>` in `web.xml` and rename to `WEB-INF/oidc.json` | Keycloak OIDC client adapter not supported; use built-in Elytron OIDC | OIDC Migration |
| Vault expressions: `${VAULT::` → Elytron encrypted expressions | structural | `${VAULT::vault_block::attribute::sharedKey}` | Elytron encrypted expression via `credential-store` | Search deployment files and annotations for `${VAULT::` | Vault Migration |
| Custom login modules: PicketBox `LoginModule` → Elytron `jaas-realm` | structural | Custom `LoginModule` in legacy security domain | Configure `jaas-realm` in `elytron` subsystem | Does NOT support modules extending PicketBox APIs; prefer `jdbc-realm` or `ldap-realm` | Security Removal |
| EJB remote: default port 4447 → 8080 | structural | `remote.connection.default.port=4447` | `remote.connection.default.port=8080` | Update `jboss-ejb-client.properties` or `wildfly-config.xml` | EJB Client Changes |
| EJB remote: `remote` connector → `http-remoting` | structural | `remote.connection.default.protocol=remote` | Default is `http-remoting`; only set explicitly when connecting to EAP 6 | New default connector for EAP 7+ | EJB Client Changes |
| JNDI provider URL: `remote://` → `http-remoting://` | structural | `java.naming.provider.url=remote://localhost:4447` | `java.naming.provider.url=http-remoting://localhost:8080` | Update remote naming client code | EJB Client Changes |
| EJB client config: `jboss-ejb-client.properties` → `wildfly-config.xml` | structural | `jboss-ejb-client.properties` + programmatic `Properties` | `META-INF/wildfly-config.xml` with unified Elytron auth config | `wildfly-config.xml` unifies EJB, naming, and auth client config | EJB Client Changes |
| Messaging descriptor: HornetQ → ActiveMQ Artemis namespace | structural | `xmlns="urn:jboss:messaging-deployment:1.0"` + `<hornetq-server>` | `xmlns="urn:jboss:messaging-activemq-deployment:1.0"` + `<server>` | Update `-jms.xml` deployment descriptors | Messaging Changes |
| HornetQ API replaced by ActiveMQ Artemis | structural | `org.hornetq.*` API classes | `org.apache.activemq.artemis.*` API classes | ActiveMQ Artemis is an evolution of HornetQ; similar concepts | Messaging Changes |
| Messaging: auto-create JMS attributes deprecated | structural | `auto-create-jms-queues`, `auto-create-jms-topics` | `auto-create-queues`, `auto-create-addresses` | Deprecated attrs no longer take effect in EAP 8; replacements default to `true` | Messaging Changes |
| Messaging: embedded broker requires explicit Galleon layer | structural | Embedded broker included in default EAP 7 install | Add `embedded-activemq` Galleon layer explicitly | Not part of default EAP 8 config; recommended to use dedicated AMQ cluster | Messaging Changes |
| mod_cluster: `proxy-list` attribute removed | structural | `proxy-list="host1:port1,host2:port2"` | Use `proxies` attribute (list of outbound socket binding names) | `proxy-list` deprecated in EAP 7.4, removed in EAP 8.0 | mod_cluster Changes |
| mod_cluster: `connector` attribute → `listener` | structural | `connector="ajp"` | `listener="ajp"` | Deprecated `connector` attribute removed in EAP 8.0 | mod_cluster Changes |
| mod_cluster config path changed | structural | `/subsystem=modcluster/mod-cluster-config=configuration` | `/subsystem=modcluster/proxy=default` | Update management CLI scripts | mod_cluster Changes |
| Undertow: `Server` and `X-Powered-By` response headers removed from defaults | behavioral | Response headers `Server: JBoss-EAP/7` and `X-Powered-By: Undertow/1` added by default | Headers removed to prevent server info disclosure | Since EAP 7.2; apps relying on these headers must add them explicitly | Undertow Changes |
| Undertow: `security-realm` → `ssl-context` for HTTPS listeners | structural | `<https-listener security-realm="ApplicationRealm">` | `<https-listener ssl-context="applicationSSC">` | Elytron `ssl-context` replaces legacy security realm for TLS | Undertow Changes |
| Undertow: `http-invoker` uses Elytron auth factory | structural | `<http-invoker security-realm="ApplicationRealm"/>` | `<http-invoker http-authentication-factory="application-http-authentication"/>` | Legacy security realm reference → Elytron authentication factory | Undertow Changes |
| EJB subsystem: `cache`/`passivation-store` → `simple-cache`/`distributable-cache` | structural | `/subsystem=ejb3/cache`, `/subsystem=ejb3/passivation-store` | `/subsystem=ejb3/simple-cache`, `/subsystem=ejb3/distributable-cache` + `distributable-ejb` subsystem | Deprecated in EAP 8; migrate to new resources for future compat | EJB Subsystem Changes |
| RESTEasy: Jackson provider upgrade 1.x → 2.x | structural | `org.codehaus.jackson.annotate.*` annotations | `com.fasterxml.jackson.annotation.*` annotations | `resteasy-jackson-provider` → `resteasy-jackson2-provider` | RESTEasy Changes |
| RESTEasy: security filters return 403 instead of 401 | behavioral | `@RolesAllowed`, `@DenyAll` returned 401 Unauthorized | Now return 403 Forbidden | Since RESTEasy 3.x; may affect client error handling | RESTEasy Changes |
| RESTEasy: `@Produces`/`@Consumes` now required on endpoints | behavioral | Endpoints without `@Produces` could work | Missing `@Produces`/`@Consumes` may cause `NoMessageBodyWriterFoundFailure` | Add explicit media type annotations to all REST endpoints | RESTEasy Changes |
| JAX-RPC no longer supported; use Jakarta XML Web Services | removal | JAX-RPC web services with `<jaxrpc-mapping-file>` | Migrate to Jakarta XML Web Services (`@WebService`) | Identify by `<java-wsdl-mapping>` root element or `webservices.xml` with `<jaxrpc-mapping-file>` | Web Services Changes |
| WS-Security: RSA v1.5 key transport disallowed by default | behavioral | RSA v1.5 key transport algorithm allowed | RSA v1.5 and related algorithms disallowed by default | Re-enable explicitly if needed for backwards compatibility | WS-Security Changes |
| `jbossws-cxf.xml` Spring integration no longer supported | removal | `jbossws-cxf.xml` with Spring-based CXF interceptor chains | Use JBossWS descriptor (`jaxws-endpoint-config.xml`) for interceptors and features | Replace Spring configs with `cxf.interceptors.in`/`cxf.interceptors.out` properties | Web Services Changes |
| JBoss Logging annotations moved to separate package and artifact | structural | `import org.jboss.logging.Cause;` | `import org.jboss.logging.annotations.Cause;` | Add Maven dependency `org.jboss.logging:jboss-logging-annotations`; `BasicLogger` and `Logger` unchanged | JBoss Logging Changes |
| HTTP Session ID format changed | behavioral | `request.getSession().getId()` returned `session-id.instance-id` | Returns only the session ID (no instance ID suffix) | May affect JSESSIONID cookie recreation logic | HTTP Session Changes |
| Custom Catalina valves must be replaced with Undertow handlers | structural | `<valve><class-name>org.apache.catalina.valves.ValveBase</class-name></valve>` in `jboss-web.xml` | Implement custom Undertow handler | JBoss Web replaced by Undertow; `ValveBase` no longer available | Undertow Changes |
| `org.jboss.security.ignoreHttpsHost` → `cxf.tls-client.disableCNCheck` | structural | `-Dorg.jboss.security.ignoreHttpsHost=true` | `-Dcxf.tls-client.disableCNCheck=true` | System property for disabling HTTPS CN check renamed | WS-Security Changes |
